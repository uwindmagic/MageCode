# AI 中台 — 架构决策记录 v0.1

日期：2026-10-25。状态：供评审的推荐基线。用户已明确后端使用 Rust，其他细化项待实现验证。

## ADR-001：Tauri 2 桌面壳，React 界面，独立 Rust 核心

背景：需要三端桌面体验、本地工具集成；用户后续后端采用 Rust。

决策：Tauri 2 + React/TypeScript；Rust 用例和存储接口独立于 Tauri。桌面默认使用 IPC，首期不开放 HTTP 端口。

收益：Rust 同时服务桌面与后续后端，界面组件可复用，运行时相对轻。

成本：需要 Rust 与前端协作，系统 WebView 表现不同；三端文件、凭据和打包必须分别验证。

备选：Electron 提供更一致的 Chromium，但带来较大运行时，Rust 还要额外桥接；在用户确认 Rust 方向后不作为首选。Flutter 需额外 Dart/Rust 桥接；纯 Web 对本地工具控制受限。若 P0 发现明确的 WebView 兼容障碍，再评估替换桌面壳，保留 Rust 核心。

## ADR-002：模块化单体，适配器先随应用编译

背景：个人本地工作台需要多来源接入，尚无独立部署或横向扩容需求。

决策：core、infrastructure、desktop 三个边界；适配器用普通 Rust 接口注册；个别来源需要隔离时再子进程化。

收益：开发、调试、部署简单，业务边界清晰。

成本：进程内适配器故障可能影响整个应用，必须限制 IO、解析、并发并处理错误。

备选：微服务、消息中间件、动态库插件会增加运维和 ABI 成本，当前不选。

## ADR-003：SQLite 管中台数据，来源只读

背景：要关联项目、索引消息、保存用户归类，并支持离线。

决策：SQLx + SQLite/FTS5，WAL、事务迁移、缓存重建与用户数据保全；数据库放本机应用数据目录。中文 trigram 与短词回退先测量。

收益：无需安装数据库服务，事务和关联查询适合本场景。

成本：写入并发要收敛，百万级语料的中文检索需要实测，备份要处理 WAL 一致性。

备选：PostgreSQL 适合后续多用户服务；当前维护成本偏高。独立搜索服务和向量库首期不引入。

## ADR-004：统一项目与原生项目分离

背景：一个真实项目可能分布在不同 Agent 中，同名原生项目不一定是同一项目。

决策：HubProject 聚合 NativeProject，Session 保留原始身份；两套导航引用同一 Session。自动匹配只提建议，用户可以覆盖。

收益：跨工具检索与原生层级同时成立，可追溯原会话。

成本：需维护映射、待归类入口与冲突处理。

备选：按目录名直接合并容易串项目；完全复制会话到各视图容易产生重复与漂移，均不选。

## ADR-005：按真实能力逐级对接，先读后写

背景：各工具的读取、跳转、恢复、发送能力不同，CLI 或 API 的存在不证明能恢复既有会话。

决策：能力逐项探测并记录证据；先索引阅读，再挑一个工具实现完整原会话恢复。真实接续必须验证发送前后的原生 ID 与消息。

收益：不会把模型 API 对话冒充原 Agent 对话，可用能力逐步交付。

成本：不同工具用户体验可能不同，兼容性需跟随版本维护。

备选：统一浏览器自动点击脆弱且难以可靠恢复；直接改写来源数据库可能破坏原应用，均不作为基础集成方案。

## ADR-006：来源指标、估算、未知分开显示

背景：累计输入、模型窗口、当前上下文、账号额度并非同一指标。

决策：每项指标记录范围、单位、来源、时间和测量方式；不可得时显示未知；不同模型或压缩阶段不直接相加算上下文占比。

收益：面板信息可解释，避免伪精确。

成本：部分工具首期有空值，需在 UI 中说明。

备选：一律用累计 Token 或字数填满面板会误导，故不选。

## ADR-007：Axum 是后续可选入口

背景：用户计划用 Rust 做后端，但当前用途是本地桌面工作台。

决策：Rust 核心独立、DTO 版本化；需要独立服务时再增加 Axum HTTP/SSE 入口和认证。远端数据采集需在来源设备上运行独立组件。

收益：避免首期维护额外服务，又保留核心复用路径。

成本：远程化仍需补充权限、多设备定位和网络恢复，不能仅增加一个路由就宣称完成。

备选：一开始全量服务化增加端口、认证、部署负担；把逻辑全写进 Tauri 命令则难以复用，均不选。
