## 用户需求原文

> 我们不做全量历史迁移，仅显示对话结果，过程中出现的分析一律不显示，但是采集到的数据可以建立本地数据库，我们需要不定时对数据库进行同步以在前端获取最新对话，这个同步规则我们之后再定；
>
> 我们的数据库将为所有工具建立一套，请你挖掘其他agent本地数据结构并设计数据库；
>
> 我们的界面显示结构为两个分支，一个是按项目，这个项目不局限于单个agent中的项目，而是若多个项目共用一个主文件夹目录，则该项目里会包含不同工具的会话；
>
> 另一个分支按工具，则是以每个工具各自的项目组织进行会话显示；
>
> 请按以上行动，版本需求和记录要同步到H:\PARA\2.Area\AI中台_Agent都在干什么_20261026里

## 需求解释与边界

1. 不保存或展示分析、过程评论、工具调用、工具结果、运行轨迹；数据库是“用户消息 + 明确最终答复”的展示投影，不是原始历史镜像。
2. Codex 助手消息仅接受 `phase=final`。缺失或未知 phase 的旧助手记录不猜测为最终答复；用户消息保留。原始 JSONL 始终只读。
3. 所有工具共享一个 MageCode SQLite 数据库，以 connection 隔离来源身份，不为每个工具各建一套业务库。
4. 按项目：以规范化共享主目录聚合不同连接的原生项目；按工具：保留工具自己的原生项目路径和组织。
5. Windows 路径统一斜杠、忽略大小写、移除普通尾部分隔符；不根据同名、相似名或父子目录自动合并。
6. 本版仅提供手动同步和启动读取已有快照，不创建定时任务，不确定自动同步频率。
7. 其他 Agent 的真实格式调查写入支持矩阵；未获得样本或未验证正文格式的工具不进入真实数据列表。

## 验收结果

- Codex 列表与消息已从统一 SQLite 读取；设置页手动同步后更新快照。
- commentary、缺失 phase、developer 和 function_call 回归样例均被排除。
- 重复同步不产生重复会话或消息，用户注释不因重同步丢失。
- 共享目录身份由数据库映射提供；原生项目字段仍用于按工具分组。
- WorkBuddy、Trae CN、Kimi、千问办公的结构调查已完成到本版记录所述深度；其余工具标记无样本或未定位。
