# MageCode v0.3.0 版本记录

日期：2026-10-25
需求：REQ-010
架构文档：v0.4.0

## 本版目标

建立所有 Agent 共用的本地 SQLite 展示投影，只显示用户消息与最终答复；以共享主目录和工具原生项目实现两套导航。Codex 作为首个已验证真实连接器，其他 Agent 先完成本机结构调查，不把未验证格式写成已支持。

## 已实现

- 统一数据库：`tools`、`connections`、`hub_projects`、`native_projects`、`project_mappings`、`sessions`、`session_project_links`、`messages`、用户注释及同步记录表。
- 数据库位于系统应用数据目录，启用 foreign keys、WAL 和 busy timeout；来源数据库与 JSONL 保持只读。
- Codex 手动同步：设置页“同步 Codex”扫描、过滤并事务写入；应用启动只读取已有快照，没有定时同步或后台监听。
- 最终答复过滤：仅保留用户消息及 `phase=final` 的助手消息；commentary、缺失/未知 phase、developer、工具调用和工具结果不进入展示库。
- 幂等与用户数据：会话/消息按连接内原生 ID 去重，重复同步不重复；用户注释分表，重同步保留。
- 双视图身份：“按项目”使用规范化共享主目录及映射；“按工具”使用原生项目目录。两种视图读取同一批数据库会话。
- Windows 路径归一化处理斜杠、大小写和普通尾部分隔符；不按同名或父子关系误合并。
- 保留 Codex 原会话跳转、真实会话只读保护、演示数据分离和既有导航能力。
- 完成 Kimi、千问办公、WorkBuddy、Trae CN 的真实结构抽样调查，并记录 Claude Code、豆包工作、Deepseek Harness 的样本缺口。

## 明确限制

- 当前只有 Codex 真实接入；跨工具共享目录归并已有模型和测试，但需第二个连接器接入后做真实端到端展示验收。
- 缺少 final 标记的旧 Codex 助手记录不显示，避免把历史过程评论误判为结果。
- 当前手动同步重新扫描 Codex 并重建各会话的过滤展示消息；`sync_cursors` 仅记录快照计数，不是增量游标。同步频率、删除与增量规则以后确定。
- 全库正文搜索、分页 DTO、core/infrastructure 分层、实时状态、Token、双向续聊及其他工具真实连接尚未实现。
- 浏览器预览只有演示数据；真实本地数据仅在桌面窗口可用。
